# Contributor Code of Conduct

All Shards-MCP collaboration spaces should remain professional, technically rigorous and accessible. Apply this to issues, code review, discussions and project-organised spaces.

## Expected behaviour

Review ideas and code rather than attacking contributors. State technical objections with evidence, acknowledge uncertainty, respect privacy, credit others' work and give actionable feedback. Avoid sharing passwords, private customer data or unpatched vulnerability details in public threads.

## Unacceptable behaviour

Harassment, discriminatory abuse, threats, stalking, doxxing, sexual harassment, deliberately malicious reviews, sustained personal attacks and intimidation. Technical disagreement and critical assessment are not harassment when directed at evidence and work.

## Reporting and enforcement

Report project conduct issues privately to organisation maintainers using GitHub's available private contact/reporting route; do **not** post identities or sensitive evidence publicly. For security vulnerabilities, follow [SECURITY.md](SECURITY.md), not public issue comments.

Maintainers may warn, moderate, temporarily restrict or permanently ban accounts based on severity, repeated behaviour and safety risk. Reports should be handled impartially, access-limited and with due consideration for privacy and appeals where practical. **No guaranteed turnaround or external appeal process is represented** before a staffed programme is established.

This policy is a project collaboration rule, not a substitute for platform terms or applicable law.
